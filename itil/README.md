# ITIL 4 artefacts — Thusa

Lightweight, one-operator ITIL: just enough process to keep a public-interest data service honest. Every artefact here is meant to be *used*, not admired.

| Artefact | File | ITIL 4 practice |
|---|---|---|
| Practice map (SVS, value chain, practices) | [itil-practice-map.md](itil-practice-map.md) | all |
| Service catalogue entry / service definition | [service-definition.md](service-definition.md) | Service catalogue mgmt, Service level mgmt |
| SLA / SLO draft | [sla-slo.md](sla-slo.md) | Service level mgmt, Monitoring & event mgmt |
| Change enablement policy | [change-enablement.md](change-enablement.md) | Change enablement |
| Change request template | [templates/change-request.md](templates/change-request.md) | Change enablement |
| Incident record template | [templates/incident-record.md](templates/incident-record.md) | Incident mgmt |
| Problem record template | [templates/problem-record.md](templates/problem-record.md) | Problem mgmt |
| Release checklist | [templates/release-checklist.md](templates/release-checklist.md) | Release mgmt, Deployment mgmt |
| Risk register | [registers/risk-register.md](registers/risk-register.md) | Risk mgmt, Info security mgmt |
| Configuration item register | [registers/ci-register.md](registers/ci-register.md) | Service configuration mgmt |
| Continual improvement register | [registers/csi-register.md](registers/csi-register.md) | Continual improvement |
| Change log / incident log | [registers/change-log.md](registers/change-log.md), [registers/incident-log.md](registers/incident-log.md) | Change, Incident |
| Runbooks & known errors | [knowledge/](knowledge/) | Knowledge mgmt, Problem mgmt |
| Decision log (ADRs) | [../docs/adr/](../docs/adr/) | Architecture mgmt, Knowledge mgmt |

Records live as Markdown in git: the git history *is* the audit trail. IDs: `CHG-YYYY-NNN`, `INC-YYYY-NNN`, `PRB-YYYY-NNN`, `REL-YYYY.MM.N`, `RSK-NNN`, `CI-NNN`, `CSI-NNN`, `ADR-NNNN`.
